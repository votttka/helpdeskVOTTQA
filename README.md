# HelpDesk Prototype

Интерактивный прототип desktop-интерфейса службы поддержки в светлом aerodesign-стиле (референсы: Zendesk, Jira Service Management, Intercom, Linear).

> ⚠️ Это **фронтенд-прототип без backend**. Все данные хранятся в `localStorage` браузера. Никаких реальных API, авторизации и инфраструктуры.

## 🚀 Быстрый старт

```bash
npm install
npm run dev
```

Откроется на `http://localhost:5173`.

## 📦 Сборка

```bash
npm run build
```

Готовый сайт появится в папке `dist/`.

## 🌐 Публикация в интернет (получить ссылку)

Есть несколько вариантов — от самого простого к более гибкому:

### Вариант 1. Vercel (рекомендуется, 2 минуты)

1. Залейте код в GitHub-репозиторий (см. раздел ниже).
2. Зайдите на [vercel.com](https://vercel.com) → войдите через GitHub.
3. Нажмите **Add New → Project** → выберите ваш репозиторий.
4. Vercel сам определит Vite и задеплоит. Готовая ссылка вида `https://helpdesk-xxx.vercel.app` появится автоматически.
5. При каждом `git push` — автодеплой.

### Вариант 2. Netlify (аналогично)

1. Залейте в GitHub.
2. На [netlify.com](https://netlify.com) → **Add new site → Import an existing project** → выберите репозиторий.
3. Build command: `npm run build`, Publish directory: `dist`.
4. Получите ссылку вида `https://xxx.netlify.app`.

### Вариант 3. GitHub Pages

1. Откройте `vite.config.js` и добавьте `base: '/<имя-репозитория>/'`:
   ```js
   export default defineConfig({
     base: '/helpdesk-prototype/',
     // ...
   })
   ```
2. Задеплойте:
   ```bash
   npm run build
   npx gh-pages -d dist
   ```
3. Ссылка: `https://<ваш-логин>.github.io/<имя-репозитория>/`.

### Вариант 4. Cloudflare Pages

Аналогично Vercel/Netlify — подключаете GitHub, указываете `npm run build` и `dist`.

## 🎨 Что внутри

### Основные разделы

- **Дашборд** — KPI-карточки, графики динамики и распределения по статусам, источники заявок, активные сценарии, статистика звонков, таблица «Требуют внимания».
- **Список заявок** — фильтры (статус, тип, источник, приоритет, исполнитель), мульти-выбор, SLA-бейджи, контекстное меню, пагинация, быстрые чипы (УСП, Без исполнителя, Без типа, Приоритет «Сейчас»).
- **Карточка заявки** — вкладки «Обзор / Взаимодействия / Аудит-лог / Связанные», правая панель с SLA, таксономией, приоритетом исполнителя, влиянием на загрузку, звонками, AI-помощником.
- **Классификация** — рабочее место классификатора с очередью заявок, загрузкой сотрудников, расчётом КЗ, модальным окном классификации.
- **Сценарии** — управляемые сценарии обработки заявок (массовые инциденты, аварии, пиковая нагрузка).
- **Настройки** — 9 вкладок: статусы, переходы, таксономия, автоматика, SLA, воронки, сценарии, роли, интеграции.

### Модальные окна и drawer

- **Смена статуса** — с динамическими полями под каждый переход (включая новый статус «Согласование»).
- **Передача заявки** — с указанием линии, исполнителя, причины.
- **Новая заявка** — drawer справа с валидацией.
- **Суфлёр AI** — чатовый помощник внутри заявки с быстрыми действиями.

### Ключевые фичи

#### 1. Таксономия
- **8 групп** и **42 типа** обращений с плановым временем
- Примеры групп: Обновление конфигурации, Ошибки и инциденты, Регламентированная отчётность, Обмен данными, Права и доступы, Консультации, Платные работы, Внутренние задачи
- Примеры типов: Добавление пользователя (0.5 ч), Сброс пароля (0.3 ч), Обновление конфигурации (2 ч), Настройка отчёта (4 ч) и др.
- Отображается в списке заявок, карточке, фильтрах, окне классификатора, настройках

#### 2. Источник УСП
- Поле «Источник» с 8 вариантами: УСП, Телефон, Почта, Чат, Портал, Внутренняя задача, Мессенджер, Ручной ввод
- Бейдж УСП с внешним номером (например, УСП-10234)
- Тип контракта: Госконтракт / Коммерческий / Внутренний
- Фильтры и быстрые чипы в списке заявок
- Статистика на дашборде

#### 3. Приоритет исполнителя
- 4 уровня: Сейчас / Сегодня / Завтра / На этой неделе
- Цветовая индикация: красный → оранжевый → синий → серый
- Устанавливается только исполнителем (классификатор видит, но не меняет)
- Влияет на расчёт коэффициента загрузки

#### 4. Коэффициент загрузки (КЗ)
- Формула: `КЗ = Σ(Плановое время × Вес статуса × Вес приоритета) / Доступное время`
- Веса статусов: В работе=1.0, Пауза=0.8, Согласование=0.3, Ждём ответа=0.2, Новая/Классификация=0, Закрыта/Архив=0
- Веса приоритетов: Сейчас=1.0, Сегодня=0.7, Завтра=0.3, На этой неделе=0.1, Не задан=0.7
- Цветовая индикация: зелёный (<0.7 — свободен), жёлтый (0.7-1.0 — норма), красный (>1.0 — перегруз)
- Отображается в окне классификатора, карточке сотрудника, tooltip с формулой

#### 5. Окно классификатора
- Отдельный раздел в навигации (доступен ролям: Классификатор, Админ, Лид)
- KPI: без исполнителя, без типа, из УСП, просрочено, средний КЗ, перегруженные сотрудники
- Очередь заявок на классификацию с фильтрами по источнику и линии
- Карточки сотрудников с загрузкой, распределением по приоритетам и статусам, прогресс-баром КЗ
- Модальное окно классификации с деревом таксономии, поиском, выбором исполнителя, отображением КЗ
- Формула КЗ с подробным объяснением весов

#### 6. Сценарии
- Отдельный раздел в навигации (доступен ролям: Админ, Лид, Аудитор)
- Демо-сценарии: Массовый инцидент УСП, Авария по УСП, Пиковая нагрузка, Срочные госконтракты
- Включение/выключение одной кнопкой
- Редактирование условий (источник, таксономия, порог похожих заявок, тип контракта)
- Действия (теги, назначение линии, статус, баннер, черновик ответа)
- Подсказка приоритета (не устанавливает принудительно)
- Отображение активных сценариев на дашборде и в карточке заявки

#### 7. Суфлёр AI
- Drawer справа с чатовым интерфейсом
- Контекст заявки (номер, тип, статус, клиент)
- Быстрые действия: суммаризация, решение, черновик ответа клиенту, черновик итога, найти статью, проверить качество, что дальше
- Фиктивные ответы с карточками действий (вставить, копировать)
- Кнопки в шапке карточки заявки, вкладке взаимодействий, правой панели
- Иконка искр, фиолетовый акцент, подпись «Демо, без реального AI»

#### 8. Статус «Согласование»
- Добавлен в статусную модель (бирюзовый цвет #06B6D4)
- Правила переходов: В работе → Согласование → В работе / Ждём ответа / Закрыта
- Отображается везде: фильтры, бейджи, модальные окна, матрица переходов, воронки, дашборд

#### 9. Звонки и подключения
- Список звонков с направлением (входящий/исходящий/пропущенный), контактом, длительностью, источником
- Статус записи и анализа
- AI-анализ звонка (фиктивный): резюме, тезисы, решения, рекомендованный итог, качество, настроение клиента
- Подключения: AnyDesk, RDP, удалённый сеанс с временем и комментарием
- Подзадачи/наряды со статусом и плановым временем

### Роли и права

- **Оператор** — дашборд, заявки, создание, классификация, комментарии
- **Инженер** — мои заявки, приоритет, статусы, звонки, подключения, AI-суфлёр
- **Классификатор** — окно классификации, назначение типа и исполнителя, КЗ сотрудников, УСП
- **Супервизор** — загрузка команды, приоритеты, переназначение, передача, bulk-действия
- **Лид** — аналитика, КЗ, сценарии (просмотр), отчёты, экспорт
- **Администратор** — полный доступ: таксономия, сценарии, настройки, сброс данных
- **Аудитор** — только чтение: заявки, аудит-лог, сценарии, КЗ

### Автоматика и таймеры

- Демо-движок работает на frontend/localStorage
- Таймеры обновляются визуально каждые 5 секунд, пересчёт правил каждые 15 секунд
- SLA идёт в статусах Новая, Классификация, В работе
- SLA останавливается в «Ждём ответа» и в «Пауза» (если причина из разрешённого списка)
- При истечении ожидания заявка автоматически переходит в целевой статус
- При окончании паузы заявка автоматически возвращается в «В работе»
- При просрочке SLA бейдж статуса и SLA становятся красными
- Каждое автодействие пишется в аудит-лог как автор «Система / Автоматика»

## 🔒 Данные

Все данные живут только в браузере. При первом запуске генерируются **60+ синтетических заявок** с разными статусами, источниками, приоритетами, таксономией, сценариями.

**Обязательные демо-данные:**
- 20+ заявок из УСП
- 10+ заявок с госконтрактами
- 5+ массовых инцидентов
- 5+ заявок без типа
- 5+ заявок без исполнителя
- 10+ заявок с назначенным исполнителем
- 15+ заявок с разными приоритетами
- 5+ заявок с приоритетом «Сейчас»
- 5+ заявок с приоритетом «Не задан»
- 10+ заявок со звонками
- 3+ заявки с проанализированными звонками
- 5+ заявок с подключениями
- 5+ заявок с внутренними задачами
- 3+ просроченных по SLA
- 3+ близких к просрочке
- 3+ заявки с активным сценарием

**Сотрудники:**
- 8 синтетических сотрудников (инженеры, методолог, классификатор, супервизор, лид, админ)
- У каждого 3-8 активных заявок
- Рассчитан КЗ
- 1-2 перегруженных сотрудника (КЗ > 1.0)
- 1-2 свободных сотрудника (КЗ < 0.7)

Используются только вымышленные клиенты: ООО «Ромашка», АО «Технопарк», ИП Иванов И.И., ГУП «Городские системы», ООО «Прогресс», АО «Стандарт», ООО «ИнфоСервис». Никаких реальных ФИО, телефонов, ИНН и внешних интеграций.

Кнопка **«Сбросить демо-данные»** в сайдбаре или меню аватара возвращает всё к начальному состоянию.
